# Воспроизводимое AI-демо (русский)

[English version](ai-demo.md)

Эта инструкция создаёт пять русских карточек со ссылками на источники из
публичного синтетического корпуса. Личные файлы, действующая автоматизация,
предыдущий чат, OpenAI API и интернет для Python-этапа не нужны.

Все события, цитаты и исследовательские заметки в `sample_corpus/` вымышлены.
Названия исторических произведений в путях только проверяют классификацию.

## Что нужно

- Python 3.11;
- приложение Codex для AI-этапа;
- Git — только если вы предпочитаете клонирование вместо ZIP.

## Получение проекта и установка

Самый простой способ не требует Git: на странице GitHub нажмите
**Code → Download ZIP**, распакуйте архив и откройте PowerShell в его корневой
папке. Разработчики могут вместо этого выполнить
`git clone https://github.com/Shellyspike/TairaSearch.git`.

В корне скачанного проекта выполните:

```powershell
python -m venv .venv
.venv\Scripts\python -c "import sys; assert sys.prefix != sys.base_prefix, 'Сломанное виртуальное окружение'; print(sys.version); print(sys.prefix)"
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -c "import pypdf; print(pypdf.__version__)"
```

На macOS/Linux:

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Если проверка `sys.prefix` не прошла, не устанавливайте зависимости. На
текущем компьютере разработчика песочница Codex иногда запускает базовый
Python вместо корректной Windows `.venv`; это не признано общей проблемой
Windows или кириллических путей. В таком случае выполните установку в обычном
PowerShell. Отдельному worktree нужно своё проверенное окружение. См.
[официальную инструкцию](https://learn.chatgpt.com/docs/environments/local-environment).

## Основной путь: один запрос в приложении Codex

Откройте папку репозитория как локальный проект Codex, начните чат в этой папке
и вставьте полное содержимое `examples/demo/codex-request.ru.md`.

Один запрос поручает Codex:

1. запустить `run_demo.py`;
2. проверить пять кандидатов в `work/demo/ai-input.json`;
3. прочитать редакционные правила и доказательства;
4. написать пять карточек `[ДЕМО]` в `work/demo/ai-cards.ru.md`;
5. проверить все ссылки на чанки события и исследовательской заметки.

Не запускайте `run_demo.py` заранее в этом сценарии. Python-поиск и AI-анализ
выполняются в одном чате, без вложенного запуска второй модели.

## Запасной путь: Python в обычном PowerShell

Если Codex не может запустить Python из `.venv`, не устанавливайте зависимости
в системный Python. Откройте обычный PowerShell в папке проекта и сначала ещё
раз убедитесь, что проверка `sys.prefix` из раздела установки проходит. Затем:

```powershell
.venv\Scripts\python run_demo.py
```

На macOS/Linux: `.venv/bin/python run_demo.py`.

Убедитесь, что появился `work/demo/ai-input.json`. Вернитесь в тот же проект
Codex и вставьте готовый короткий запрос
`examples/demo/codex-request-existing-input.ru.md`. Этот запрос поручает Codex
прочитать существующий JSON и создать `work/demo/ai-cards.ru.md`, не запуская
`run_demo.py`, Python или установку зависимостей повторно.

## Только Python

Чтобы проверить поиск без AI:

```powershell
.venv\Scripts\python run_demo.py
```

На macOS/Linux: `.venv/bin/python run_demo.py`.

Команда создаёт только игнорируемые файлы в `work/demo/`: SQLite-индекс,
`search.jsonl`, пять кандидатов, `ai-input.json`, диагностику и пустой
демо-журнал. В `ai-input.json` входят контекст события и отдельно найденная
синтетическая научная заметка. Python не вызывает модель и не пишет карточки.

## Проверка результата

В `work/demo/ai-cards.ru.md` должны быть:

- ровно пять заголовков `[ДЕМО]` в порядке кандидатов;
- предупреждение о вымышленном материале в каждой карточке;
- интересный рассказ о событии, а не комментарий о работе поиска;
- явное различие между источником, литературной сценой, исследовательской
  интерпретацией и осторожным выводом модели;
- путь и `chunk_id` события и связанной заметки;
- никаких придуманных фактов, публикации или обновления журнала.

Сравните структуру с `examples/demo/ai-output.md`. Это проверенный результат
сеанса Codex, а не текст, автоматически создаваемый тестами; формулировки новой
генерации могут отличаться.

```powershell
.venv\Scripts\python -m unittest tests.test_demo_workflow -v
.venv\Scripts\python make_release.py --check-only
```

Python отвечает за извлечение, индекс, BM25, контекст, дедупликацию и подбор
материалов. Codex выбирает подтверждённый ракурс и пишет текст. Человек проверяет
доказательства и решает, можно ли что-либо публиковать.
