# TairaSearch

**Русский быстрый старт** · [Подробное AI-демо](docs/ai-demo.ru.md) ·
[Готовый русский запрос для Codex](examples/demo/codex-request.ru.md) ·
[English README](README.md)

TairaSearch — небольшой локальный AI-проект для поиска человеческих историй в
многоязычном историческом корпусе. Детерминированный Python извлекает текст,
строит SQLite FTS5/BM25-индекс, проверяет соседние чанки, убирает повторы и
выбирает кандидатов. Codex читает найденные доказательства и пишет карточки,
которые затем проверяет человек.

Публичный репозиторий не содержит личную библиотеку автора, production-базу,
журнал публикаций, действующую автоматизацию или историю чатов. Все русские,
японские и английские демонстрационные документы, включая PDF, синтетические.

## Профильное исследование через Codex (0.3.1)

Новый пользователь может настроить поиск разговором, не редактируя JSON.
Откройте проект в Codex и отправьте один запрос:

> Прочитай `examples/codex/research-onboarding.ru.md` и проведи первоначальную
> настройку исследования.

Дальше Codex следует готовому сценарию настройки: вы указываете существующий
индекс или папку корпуса, отвечаете на несколько коротких вопросов, смотрите
пробную подборку и уточняете предпочтения обычными словами. Перед началом
подготовьте Python-окружение по инструкции ниже.

Codex сохраняет локальный игнорируемый `research_profile.json`.
`research-findings` становится основным источником кандидатов: использует
существующие FTS5, соседний контекст и дедупликацию 0.3. Codex может получать
непересекающиеся следующие партии через `--continue-from`, проверять их
свидетельства и окончательно выбирать находки. Пробная подборка не меняет
`used_finds.csv`. Подробности и два
синтетических сценария — в
[docs/research-onboarding.ru.md](docs/research-onboarding.ru.md).

Для следующих запусков используйте готовый
[исследовательский запрос](examples/codex/research-workflow.ru.md). Старый
`daily-five`, существующий индекс и демонстрация пяти карточек ниже сохранены
без изменения контрактов.

## Смысловая дедупликация (0.3)

Benchmark 0.3 сохраняет исторический результат алгоритма 0.2 на 13 вымышленных
случаях по средневековой Японии и Древнему Риму и отдельно измеряет исправленную
логику. Python теперь схлопывает только одинаковые нормализованные утверждения,
сохраняет в пуле сомнительные случаи OCR, переиндексации, пересказа, перевода и
совпадений с журналом, а также передаёт Codex ограниченный пакет сравнения.
Codex применяет четыре смысловых класса; общие персонажи, темы, даты или
названия источников, как и позиционный `chunk_id`, сами по себе не означают
повтор. Проверить
[аудит и результат реализации](docs/dedup-audit.ru.md) можно командой:

```powershell
.venv\Scripts\python run_dedup_audit.py --check
```

## Быстрый старт: пять AI-карточек

Нужны Python 3.11 и доступ к приложению Codex. Git необязателен: он нужен
только разработчикам, которые хотят клонировать репозиторий. Python сам не
вызывает модель и не требует OpenAI API key. Codex нужен только для написания
карточек.

### 1. Скачайте проект без Git и установите зависимость

На странице репозитория нажмите **Code → Download ZIP**, распакуйте архив и
откройте PowerShell в распакованной папке (обычно `TairaSearch-main`). Затем:

```powershell
python -m venv .venv
.venv\Scripts\python -c "import sys; assert sys.prefix != sys.base_prefix, 'Сломанное виртуальное окружение'; print(sys.version); print(sys.prefix)"
.venv\Scripts\python -m pip install -r requirements.txt
```

Разработчики вместо ZIP могут использовать Git:

```powershell
git clone https://github.com/Shellyspike/TairaSearch.git
cd TairaSearch
```

После клонирования выполните те же команды создания и проверки `.venv`.

Проверьте, что это Python 3.11, а `sys.prefix` заканчивается на `.venv`. Если
проверка завершилась ошибкой, не устанавливайте зависимости: иначе `pip` может
записать их в базовый Python. На macOS/Linux используйте:

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

### 2. Откройте папку и отправьте один запрос

Откройте скачанную папку `TairaSearch` как локальный проект в приложении Codex,
начните чат в этой папке и целиком вставьте запрос из
[examples/demo/codex-request.ru.md](examples/demo/codex-request.ru.md).

Codex сам запустит `run_demo.py`, прочитает созданный
`work/demo/ai-input.json`, сохранит ровно пять русских карточек `[ДЕМО]` в
`work/demo/ai-cards.ru.md` и проверит ссылки на источники. Отдельно запускать
`run_demo.py` перед этим основным запросом не нужно. Официальная
[инструкция по проектам Codex](https://learn.chatgpt.com/docs/projects?surface=app)
объясняет, как дать локальному чату доступ к папке.

### 3. Запасной путь, если Python не запускается внутри Codex

В обычном PowerShell, открытом в папке проекта, выполните:

```powershell
.venv\Scripts\python run_demo.py
```

Команда должна создать `work/demo/ai-input.json`. Затем вернитесь в чат Codex
и целиком вставьте короткий запрос из
[examples/demo/codex-request-existing-input.ru.md](examples/demo/codex-request-existing-input.ru.md).
Он прямо запрещает повторно запускать Python: Codex читает уже готовый JSON и
создаёт карточки. Не запускайте `pip` через системный Python, если проверка
`.venv` из шага 1 не прошла.

## Только Python, без Codex

Чтобы проверить индексатор и поиск без AI, выполните:

```powershell
.venv\Scripts\python run_demo.py
```

На macOS/Linux: `.venv/bin/python run_demo.py`.

Команда без интернета строит `work/demo/index.sqlite3`, выполняет
многоязычный поиск, выбирает пять кандидатов, находит для каждого синтетическую
исследовательскую заметку и создаёт `work/demo/ai-input.json`. Она не вызывает
модель. Готовые примеры доступны
[на русском](examples/demo/ai-output.md) и
[на английском](examples/demo/ai-output.en.md); это проверенные результаты
сеанса Codex, а не автоматически сгенерированные тестами файлы.

## Кто что делает

| Этап | Исполнитель |
| --- | --- |
| Чтение TXT/Markdown/JSON/PDF и разбиение на чанки | Python |
| SQLite FTS5, BM25, соседний контекст и дедупликация | Python |
| Пять кандидатов и связанные научные заметки | Python |
| Интересный ракурс, осторожный синтез и текст карточек | Codex |
| Проверка доказательств и решение о публикации | Человек |

Литературный сюжет, научная интерпретация и осторожный вывод модели всегда
должны быть явно разделены. Выразительность не разрешает придумывать факты.

## Проверка проекта

```powershell
.venv\Scripts\python -m unittest discover -s tests -v
.venv\Scripts\python run_demo.py
.venv\Scripts\python run_research_demo.py
.venv\Scripts\python run_dedup_audit.py --check
.venv\Scripts\python make_release.py --check-only
```

Поиск открывает SQLite только для чтения, но учитывает актуальные WAL-данные.
Повторная индексация сохраняет последнюю корректную версию документа при
ошибке. Обновление `used_finds.csv` атомарно, идемпотентно и защищено
межпроцессной блокировкой Windows/Linux. Публичная сборка создаётся только по
allowlist из `release_manifest.toml` и не включает локальные базы, журналы или
личные документы.

На текущем компьютере разработчика есть ограничение песочницы Codex для
стандартной Windows `.venv`: иногда запускается базовый интерпретатор. Команда
проверки `sys.prefix` обнаруживает это до установки. Это не считается общей
проблемой Windows или кириллического пути. Подробнее — в
[docs/ai-demo.ru.md](docs/ai-demo.ru.md) и [ROADMAP.md](ROADMAP.md).
